网络基础

TCP/IP模型

应用层：HTTP，规定请求和响应的格式，例如 GET /users/1。

传输层：TCP，通过端口区分应用的通信端点，并提供可靠、有序的字节流传输。

网络层：IP，提供地址，让路由器能把数据逐步转发到目标。

网络接口层：以太网、Wi-Fi 等，负责在当前链路上传输数据。

IP 和端口的区别

一台服务器上可能同时运行多个程序，比如 Java 后端、MySQL、Redis。请求到达服务器后，还要知道交给哪个程序。

标识 作用 例子
IP 地址 定位目标主机的网络地址 192.168.1.10
端口号 区分主机上的通信端点 Java 服务监听 8080，MySQL 监听 3306

应用层

HTTP 是什么？

HTTP 是一种应用层协议，规定浏览器和服务器之间，请求与响应应该怎么表达。

比如浏览器发送：

这句话表达三个信息：

  • GET：我要获取资源。
  • /users/1：我要获取编号为 1 的用户。
  • HTTP/1.1：使用的协议版本。

服务器收到后，按照 HTTP 的规则回复状态码、响应头和用户数据。

HTTP 请求报文由什么组成？

以 HTTP/1.1 为例，一份请求包含：请求行、请求头、空行、可选的请求体。

① 请求行：要做什么

POST 是请求方法，/users 是请求目标，HTTP/1.1 是协议版本。这里表示向 /users 提交数据。

② 请求头：补充说明

分别说明目标主机、请求体的数据格式，以及请求体的字节数。

③ 空行：分隔请求头和请求体

空行不是为了排版，它是报文结构的一部分。

④ 请求体：实际提交的数据

这里提交了一个名字。请求体不是每个请求都有，例如普通的 GET 查询通常没有请求体。

① 状态行：请求处理得怎么样

  • HTTP/1.1：协议版本。
  • 200：状态码，表示请求成功。
  • OK：对状态码的简短说明。

② 响应头：描述这次响应

表示响应体采用 JSON 格式，长度是 9 字节。

③ 空行：分隔响应头和响应体

④ 响应体：实际返回的数据

GET 和 POST

方法 主要语义 常见场景
GET 获取资源 查询用户、查看商品
POST 提交数据进行处理 创建用户、提交订单

GET 参数在 URL，POST 参数在请求体

POST 的数据放在请求体里，此时还不是加密状态

幂等是指同一个请求执行一次和多次，对服务端产生的预期效果相同。GET 具有幂等语义，POST 不保证幂等。

GET 具有安全语义，POST 不保证安全

HTTP 状态码

状态码第一位数字表示大类

分类 含义 例子
1xx 提示信息，后续还有处理 100
2xx 请求成功 200
3xx 重定向或缓存验证等 301、304
4xx 请求存在问题 404
5xx 服务器处理出现问题 500
