登录认证和权限校验怎么实现？

Spring Security + JWT + Redis为例，登录时核实身份，之后每次请求检查登录状态，访问具体接口时再检查权限。

登录

1. 用户输入账号、密码、验证码

前端把它们提交给后端的 /login 接口。

2. 后端检查账号密码

先校验验证码，再通过 Spring Security 查询数据库中的用户，检查账号状态，并校验密码。

验证成功后，得到一个 LoginUser，里面包含用户信息和权限。

3. 把登录信息存入 Redis

后端生成一个随机 UUID，作为这次登录的唯一标识，例如 abc123。

注意区分：

  • JWT：前端拿着的登录凭证。
  • UUID：JWT 里面的登录标识，用来查 Redis。
  • LoginUser：Redis 中保存的实际登录信息。

总结：通过 Spring Security 校验账号密码。登录成功后，生成一个 UUID，将用户信息和权限存入 Redis，再把 UUID 放进 JWT 返回给前端。后续请求携带 JWT，后端过滤器验证并解析出 UUID，到 Redis 获取登录用户，再把认证信息放入 SecurityContext，供后续权限校验使用。退出登录时删除 Redis 中的登录信息。

Java日志级别？

Spring Boot 项目中常见的是 SLF4J + Logback：

  • SLF4J：提供统一的日志接口。
  • Logback：实际负责输出日志。

日志级别

级别 常见用途
TRACE 非常细的执行过程
DEBUG 调试信息，例如中间变量
INFO 正常的关键业务事件，例如订单创建成功
WARN 出现异常情况，但暂时还能继续处理
ERROR 操作失败，需要关注和排查
